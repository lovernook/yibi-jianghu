## 决定：保留工程，重构应用层与表现层

继续使用本独立 Unity 工程，保留 2.2 成品和证据，建立新的 Framework 与展示资产目录。保留纯 C# 评分／战斗规则、协议 2 权威服务、存档数据兼容和现有测试；逐个替换巨型 Presenter、硬编码流程与临时界面。

重新开空项目会重复处理素材、URP、协议、评分和已解决的故障，不能自动提升体验。只有目标变成共享多人世界／MMO，或核心玩法、引擎和网络模型均改变时，才重新评估新工程。当前目标仍是 Windows 键鼠、小型 3D 武侠探索＋画穴位回合构筑＋真实 1v1。

Unity 2022.3.62f3c1、URP 14.0.12 暂时锁定。先做作品质量，再单独评估引擎升级，避免素材和架构同时迁移。原《星海学园》不操作。

## 成品范围与玩法目标

一段完整归云篇，设计目标约 20～30 分钟（尚未测得），一处高质量山谷、两种挑战擂台、六秘籍、两心法、一条任务主线与少量支线、练功挑战、稳定的两人论武。内容量以能完成、能复玩、能解释为上限，不扩成 MMO 或开放世界。

核心体验应从“照线获得分数”升级为“观察敌方意图→决定构筑和行动→完成有反馈的运笔→理解回合结果”。仍然是回合制，禁止把动作表现偷偷变为实时伤害结算。

- 画线：清晰起止与下一穴提示；练习可示范／回放，对战不提供自动作答；先保证鼠标手感和可解释错误，再评估路线变化。阶段 C 保留连续倍率 `0.8 + 0.4 × score / 100`，评级只帮助理解，不另设伤害档位；不能让脚本满分替代策略。
- 战斗：明确内力、冷却、护盾、破绽／蓄风／灼伤；展示敌方意图、可用组合与简短结算因果。每种敌人有可观察、可反制的套路；先用测试确定数值边界。
- 成长：主线保证获得核心构筑，支线和挑战提供选择性奖励；免费抽签退居补充，不再承担玩家理解系统的职责。新成长规则需兼容旧存档并有迁移测试。
- 任务：任务定义数据化（稳定 ID、前置、目标、奖励、对话）；运行进度独立；奖励按 ID 幂等；View 订阅任务事件，不能在每帧 UI Refresh 中发奖。
- 1v1：沿用已验证的权威回合服务；增加清楚的连接／准备／恢复／对局状态。共享多人探索、账号、匹配、公网中继与排行榜不在当前范围。

## 目标架构与迁移边界

| 层 | 职责 | 依赖原则 |
| --- | --- | --- |
| Domain | GestureScorer、BattleReducer、任务／奖励规则、不可变命令和结果 | 不引用 Unity、GameFramework、UI 或 Socket |
| Application | 启动流程、探索／战斗／房间用例、任务进度、存档和场景协调 | 通过接口使用存储／网络／资源，不查找场景 Text |
| Infrastructure | ProfileRepository、权威会话适配、内容导出、资源加载和设置持久化 | 明确生命周期、取消、释放和错误结果 |
| Presentation | View、输入适配、动画、声音、视觉反馈与导航 | 消费状态和事件；不决定伤害、奖励和任务是否完成 |

GameRoot 是统一组合入口，GameFramework Procedure/FSM 管应用流程，Event 管跨模块通知。业务战斗状态机继续由已验证 Reducer 执行，避免在两个 FSM 重复维护胜负。网络适配独立于框架，暂不重写已验证 TCP。

流程：启动校验 → 主菜单 → 异步加载 → 探索／练功／房间／战斗 → 返回。加载过程防重复点击、遮挡旧输入，失败保持可恢复，订阅成对释放，直接从任意保存场景 Play 也可用。新增依赖通过 asmdef 单向引用，并保留旧模块桥接；每迁移一个模块才移除对应旧入口。

UI 使用统一字体、间距、颜色、状态与层级规范；屏幕级、弹窗级、提示级分组，模态窗口只锁它需要锁的输入。固定页面、加载遮罩和模型必须保存为场景／Prefab，不在运行时整页用代码拼接。先做好主菜单、任务／行囊与战斗 HUD 三类页面，再扩页面数量。

资源按“源资料 → 候选 → 已验收运行资源”流转。保留原始源文件与 GUID 记录；示例视频、Maya 源文件、压缩包属于源资料，不能全部作为运行时资源。先验证绑定、动画、URP 材质、比例、碰撞和实际镜头，再替换正式角色。

资源源目录里没有许可文件时记录“授权来源待用户补充”，不反向声称未授权，也不将购买素材或原始压缩包发布到仓库。

## 质量门槛

- 工程：业务代码与第三方代码隔离；依赖锁定；核心逻辑测试；无缺失脚本／断引用；错误能定位到用户动作与模块。禁止只通过编译就称成品稳定。
- 交互：1280×720、1920×1080 与超宽屏关键页面可读；返回、取消、重复点击、断网均有明确结果；操作提示统一。
- 体验：目标清楚、路径可走、主线不软锁；首五分钟能理解“练功—构筑—战斗”的关系；同一轮只能提交一次。
- 性能：前台独立包测 CPU／GPU 与分配，加载和战斗分开统计；目标机器 1080p 60 FPS 是目标而非本轮既成结论；二十次切换没有持续增长，再补长时试验。保留 2.2 隐藏窗口数据的限定。
- 交付：完整客户端与本地服务、依赖与美术来源表、操作指南、限制、复现测试、3～5 分钟演示视频。简历只写本人能够解释并复现的模块。

## 学习与讲解

按用户偏好先实现，再集中讲解。每个模块保留“输入→用例→规则／服务→状态→View”的调用链、一个小改动和一个故障定位问题。是否独立理解必须由用户实际修改和回答验收，框架名称与助手生成代码都不能代替掌握。
