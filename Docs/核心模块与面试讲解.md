# 核心模块与面试讲解

这份文档是接手学习的入口，不是“已经掌握”的证明。实现与本轮自动检查由助手辅助完成；你需要自己修改、观察并讲述后，才能把对应能力记入学习验收。面试中如实说明辅助开发方式和本人实际负责/理解的部分。

## 先讲清作品

这是小型 3D 武侠探索作品。玩家在山谷获得并装配秘籍，战斗按回合进行。每次秘籍施放前，用鼠标按顺序连接穴位，评分参与技能效果计算；对战支持离线 NPC 和本地/局域网 TCP 双客户端。不是实时动作战斗，也没有公网匹配服务。

目前采用购买资源中的角色、建筑、植被和 UI；在四个人物源网格上补了基础自动蒙皮、21 骨骼与八种可编辑动作。重点技术是轨迹评分、确定性回合结算、服务器重新校验，以及动画表现与规则分离。购买的模型不能列为本人原创；自动生成基础动画也不等于专业角色绑定能力。新增实现及学习入口见《骨骼动作与归云篇更新.md》。

## 1. 画线评分

调用链：`GestureBoard.Update` 接收鼠标 → 屏幕位置转画板归一化坐标 → 单笔采样器限制点数、记录越界 → 量化轨迹 → Rules 中节点顺序检查与弧长重采样 → 形状/顺序/长度分项 → `ScoreResult` → 面板反馈 → 用户确认。

为何归一化：画板尺寸和分辨率变化后，输入仍落在同一坐标范围。为何量化：传输和规则层不依赖 Unity 的浮点向量类型。为何保留错误码：玩家能知道是逆序、漏点、越界还是形状偏离，调试也能定位具体原因。

小修改：复制一份路线资产，轻微移动第二个节点，保存后分别沿新、旧路径绘制，记录分项变化；先在练功场验证，不直接改线上双方版本。

调试问题：同一张看起来一样的线为什么可能逆序失败？分辨率变化后如果直接使用屏幕像素，评分会发生什么？

## 2. 回合结算

调用链：按钮选择秘籍 → `BattlePresenter.SelectSkill` 选择模板 → 画线预览 → `Confirm` 生成 `BattleCommand` → `BattleReducer.Apply` 校验回合/席位/消耗/冷却 → 复制并推进 `BattleState` → 返回事件、评分与新状态 → UI 刷新 → `BattleFeedback` 驱动骨骼动作、跳字和资源条，Presenter 驱动位移。

离线 NPC 最终也生成规则命令，不直接扣血。`resolving` 防止动画期间重复输入；规则层仍必须校验 `turnId`，不能只靠按钮变灰保证合法。伤害结算与表现分开，换人物或光效不应该改变规则结果。

小修改：在练习分支调整 NPC 选择秘籍的优先顺序，完成一场 PVE，记录它在哪一回合改为调息。先不要改公共规则常量。

调试问题：如果两次点击确认都到达规则层，应该由 UI、回合号还是动画状态决定第二次无效？为什么？

## 3. 探索、获得与存档

调用链：`ValleyExplorer.Update` 处理方向与 CharacterController → `ValleyPresenter.Update` 找最近交互点 → E 调用 `JourneyPresenter` 展示对话与条件 → 接受后 `PerformInteraction` 保存返回位置并切场景；结算后加载 Valley，Start 恢复位置。`JourneyRules.Stage` 读取成就并给出当前目标，遗匣使用稳定 ID 去重奖励。

行囊按钮 → ProfileStore 验证拥有与装配 → 修改内存数据 → 临时文件写入并替换存档，保留备份。奖励使用唯一标记避免每次返回都重复领取。抽签是作品中的免费资源机制，没有付费服务。

小修改：在非 Play 模式移动一个交互点，保存、重开场景，确认 E 提示跟着新位置出现；不要只移动装饰 NPC 而忘记实际交互点。

调试问题：模型看起来就在面前却没有 E 提示，应该先检查哪个 Transform？退出程序后装配丢失，如何区分“没写入”和“写到了不同目录”？

## 4. 双客户端

调用链：Lobby 连接/创建/加入/准备 → `NetSession` 将消息加入发送队列 → `TcpFraming` 写长度和 JSON → 服务端收满消息、验证摘要和会话 → 校验请求/回合/席位 → 使用同一 Rules 重算轨迹与结算 → 广播完整快照 → 客户端主线程应用快照 → BattlePresenter 更新画面。

客户端不会上报“我造成 30 点伤害”作为最终事实。TCP 有序可靠，但一次 Read 不等于一条消息，所以仍要长度前缀和循环收满。客户端重复发送请求时，服务通过请求标识缓存结果，避免重复扣血。网络线程不能直接修改 Unity UI，需排队交给主线程。

实际证据：已完成一场两个独立 Unity 程序对战，双方最终快照一致。尚未完成计划中的五场完整回归、公网部署或所有断线场景，因此面试不要说“生产级服务器”或“公网联机全面验证”。

小修改：先在两端显示 `revision`，观察每次合法行动后两端是否同步推进，再故意暂停一端查看重连后的快照。显示改动不应改变规则。

调试问题：客户端超时显示 0，但服务端还没发结果时，应由谁结算？相同请求重发和不同请求使用旧回合号，应怎样区别处理？

## 5. 素材与编辑器

调用链：原始 max/FBX/贴图 → 转换并修复纹理路径 → 选取单网格 → 统一尺寸、地面原点和 URP 材质 → 保存 Prefab → 场景拖放/组件引用 → 保存场景 → 运行显示。

UI 图集通过 Sprite 矩形和 Border 拆分，原图保留。固定 HUD 与场景在编辑模式存在，运行时只更新文本、状态和显隐。素材包示例失效的原因是 GUID 引用缺失，复制贴图或清空 Console 本身不能修复该关系。

小修改：在 Prefab Mode 修改一个按钮边距或树木材质，保存后观察哪些实例跟着变化、哪些因为场景覆盖而没变化。

调试问题：Play 中换完模型退出就恢复，是什么原因？改了 Prefab 后某一个场景实例没有变化，先检查什么？

## 当前边界

路线与消耗已导出为公共内容和摘要；复杂技能效果目前仍是固定规则实现。不能描述为完整的可视化技能图编辑器。计划中的专用技能/心法/擂台工具和性能报告尚不完整。先把已有调用链讲准确，再继续扩展。

学习验收方式：每个模块提交一个实际修改、一个可复现现象、对调试问题的解释；助手可以追问和检查，但不能代替你声称已经掌握。
